# analytics-service — правила для Claude

Web-бэкенд SkyPulse для аналитики (блок `svc_analytics` на схеме): считает
агрегаты поверх исторических данных YTsaurus и отдаёт их клиенту «Дашборд».

## Стек

Java 21 (toolchain) · Gradle (Kotlin DSL) · Spring Boot 3.3 (web, actuator) ·
springdoc/Swagger (авто из контроллеров) · Checkstyle 10.x (Google-style) · JUnit 5.

Стек и конвенции те же, что в `positions-service` — сервисы должны читаться
одинаково.

## Стиль кода

- Java 21: используем `record` для DTO/моделей, `var` для очевидных типов,
  стримы вместо ручных циклов там, где читаемее.
- Отступ 4 пробела, длина строки ≤ 120. Форматирование проверяет Checkstyle,
  сборка падает при нарушениях (`maxWarnings=0`).
- Именование говорящее — тогда код не нуждается в пояснениях.

## Комментарии

Пишем комментарии **только там, где без них реально не разобраться**: неочевидная
причина решения, бизнес-правило, ссылка на требование (FR/NFR), подводный камень.
Хороший комментарий объясняет **почему**, а не **что**. Комментарии и тексты
ошибок — по-русски, как в остальном проекте.

## Слои (контроллеры зовут только сервис)

```
api/         @RestController + DTO — контракт с фронтом, поля плоские;
             ApiExceptionHandler переводит доменные ошибки в HTTP-коды
service/     прикладная логика (@Service)
service/exception/     ошибки запроса и домена (InvalidRequestException и наследники)
repository/  доступ к данным: интерфейсы *Repository и их YT-реализации
repository/exception/  ошибки источника (DataSource*, MalformedRowException)
model/       доменные модели
```

Заглушек и моков в `src/main` нет — сервис всегда ходит в реальный YTsaurus.
Фейковые реализации портов живут только в тестах.

Роутинг, JSON, DI, Swagger — на Spring/springdoc, свою обвязку не пишем.
Новый эндпоинт: DTO → (repository) → service → метод `@GetMapping` в контроллере → тест.

## Проверки перед коммитом

```bash
./gradlew build   # компиляция + Checkstyle + тесты
```
