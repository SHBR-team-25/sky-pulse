# Обновление структуры проекта в AGENTS.md

Задача — привести `ai/tree-comments.json` в соответствие со структурой `src/`
и перегенерировать блок структуры в `ai/AGENTS.md`.

Контекст: обычно этот скилл нужен после того, как упал pre-commit-хук `npm run docs:tree:check` —
значит, в `src/` появились или изменились файлы, для которых нет актуального описания.
Работай так, чтобы после тебя `npm run docs:tree:check` проходил зелёным.

Все команды выполняются из каталога `frontend/`.

## Порядок работы

1. Запусти `npm run docs:tree:check`. Он печатает всё, что нужно исправить:
    - `нет описания в ai/tree-comments.json: <путь>` — нужен новый ключ;
    - `описание указывает на несуществующий путь: <путь>` — ключ-сирота, файл удалён или переименован.

2. Получи список изменённых файлов — описания пиши по коду, а не по догадке из имени файла:

    ```sh
    git diff --cached --name-only --diff-filter=ACMR -- src   # то, что уже в индексе (основной случай)
    git status --porcelain -- src                             # если индекс пуст
    ```

3. **Прочитай каждый новый и изменённый файл целиком** и только потом пиши описание.
   Для `.css`, изображений и прочих бинарных/стилевых файлов чтение необязательно —
   там достаточно имени и папки, в которой файл лежит.

4. Обнови `ai/tree-comments.json`:
    - добавь ключи для новых путей (включая новые каталоги);
    - обнови описание, если изменился смысл файла (например, поменялся эндпоинт или интервал поллинга);
    - удали ключи-сироты;
    - при переименовании — перенеси описание на новый ключ, а не пиши заново.

5. Запусти `npm run docs:tree`, затем `npm run docs:tree:check` — он должен вывести
   «структура в AGENTS.md актуальна».

6. Добавь результат в индекс, чтобы коммит прошёл:

    ```sh
    git add ai/tree-comments.json ai/AGENTS.md
    ```

    Сам коммит **не** делай.

## Границы

- Трогай только ключи для новых, изменённых, переименованных и удалённых путей.
  Чужие строки не переформулируй, даже если тебе не нравится формулировка —
  ревьюеру должен быть виден маленький diff.
- Никогда не правь блок дерева в `AGENTS.md` руками: он генерируется из `scripts/generate-tree.mjs`,
  ручная правка будет затёрта и уронит `docs:tree:check`.
- Файлы в `src/` не меняй — это задача про документацию.
- Если непонятно, за что отвечает файл (пустая заглушка, неочевидное назначение) —
  не выдумывай описание, спроси у разработчика.

## Как писать описание

- Ключ — путь от `src/` через `/`: `features/getLiveFlights/api/useLiveFlights.ts`.
- Значение — одна строка на русском, без точки в конце, в идеале до ~80 символов.
- Описывай **что файл делает**, а не что это за тип файла:
    - плохо: `хук для рейсов`, `компонент`, `утилита`;
    - хорошо: `хук GET /flights/live с поллингом раз в 3 с`.
- Указывай конкретику, которую видно только в коде: эндпоинт, интервал, ключевые экспорты, важное условие.
- Для служебных сегментов пути (`api`, `model`, `ui`, `images`) ставь пустую строку `""` —
  это осознанный отказ от комментария, скрипт такие ключи не считает пропущенными.
- Каталоги слоёв и фич описывай по назначению: `features/getAirports` → `получение списка аэропортов`.

## Пример

Разработчик добавил `src/features/getAirportStats/api/useAirportStats.ts`.
`docs:tree:check` ругается на три пути. Читаешь файл, видишь `useQuery` на `/airports/{icao}/stats`
с `staleTime: 5 минут`. Дописываешь в `ai/tree-comments.json`:

```json
"features/getAirportStats": "получение агрегированной статистики аэропорта",
"features/getAirportStats/index.ts": "публичный API фичи",
"features/getAirportStats/api": "",
"features/getAirportStats/api/useAirportStats.ts": "хук GET /airports/{icao}/stats, кэш 5 минут"
```

Дальше `npm run docs:tree` и `git add`.
